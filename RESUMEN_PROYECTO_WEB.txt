QUÉ ES
------------------------------------------------------------------------
Aplicación web (FastAPI + Playwright) que replica la automatización de
consulta a la DIAN (información exógena, determinación de renta y
facturación electrónica) pero accesible desde CUALQUIER dispositivo por
un navegador (https), sin instalar nada en el equipo del usuario.

  Repo      : https://github.com/RICORDOB/DIAN-WEB-CONSULTAS (main)
  URL prod  : https://dian-web.onrender.com
  Servicio  : srv-d9v6jam7bikc73bt9rn0 (Render, Docker)
  Tests     : pytest (75)

------------------------------------------------------------------------
ARQUITECTURA (app/)
------------------------------------------------------------------------
  main.py   -> API FastAPI + vistas HTML + gestión de jobs/batches (+ rate limit, sesiones)
  runner.py -> núcleo reutilizado: login DIAN, descargas, análisis de renta, armado .xls
  batch.py  -> motor de consultas MASIVAS: plantilla, cargar filas, ejecutar, estados
  auth.py   -> usuarios, alta por aprobación, bloqueos, roles, sesiones firmadas, historial
  db.py     -> persistencia con DOS backends: Turso (libSQL nube) y SQLite local (fallback)
  push.py   -> notificaciones push (VAPID + suscripciones)
  comun.py  -> constantes compartidas: UVT, topes, selectores, calendario de vencimientos
  bot/      -> chat de atención: cifrado (Fernet), motor de estados, tokens de descarga
  static/   -> index, panel, dev, contadores, privacidad, styles.css, app.js, bot.js, sw.js

Frontend: HTML/CSS/JS vanilla + PWA (service worker sw.js con caché versionada,
cache-buster ?v= en los assets, manifest.webmanifest). Sin framework.

------------------------------------------------------------------------
BASES DE DATOS (persistencia)
------------------------------------------------------------------------
  - Turso/libSQL (HTTP v2) si existen TURSO_DB_URL + TURSO_AUTH_TOKEN.
  - SQLite local como fallback (desarrollo/pruebas).
  - Tablas (auth.iniciar_db): usuarios, consultas, registros,
    push_suscripciones, config (VAPID), clientes_autorizados (chat bot:
    credenciales de clientes CIFRADAS con Fernet).
  - Columnas del usuario: rol (usuario|admin|contador), estado
    (pendiente|aprobado|bloqueado), acceso_contador (int, migrada
    automáticamente si no existe).

Seguridad de datos de clientes:
  - Número de documento y contraseña DIAN SOLO en memoria durante la
    consulta manual. NUNCA se persisten en esas consultas.
  - El catálogo del CHAT BOT (clientes_dian.xlsx) se sube por el admin y
    cada contraseña se CIFRA con Fernet (clave derivada de APP_SECRET_KEY)
    antes de persistir; se descifra solo en memoria al lanzar el job.
  - Las contraseñas de las cuentas se guardan con hash PBKDF2 + salt.
  - El historial guarda usuario, tipo, fechas y estado (sin documento).

------------------------------------------------------------------------
ROLES Y FLUJO
------------------------------------------------------------------------
  admin (APP_ADMIN_USER):
    - Aprueba/rechaza altas (/dev), bloquea/desbloquea (revoca sesión
      en vivo), ELIMINA cuentas, activa/desactiva Contador.
    - No puede modificarse/bloquearse/eliminarse a sí mismo.
  usuario común:
    - Registro queda 'pendiente'; entra solo tras aprobación (/panel).
  contador:
    - Usuario con acceso_contador activado por el admin; entra a
      /contadores para consultas masivas de pago.

Flujo de alta:
  1) Usuario se registra (/) -> pendiente.
  2) Admin aprueba desde /dev.
  3) Usuario inicia sesión y usa /panel.

------------------------------------------------------------------------
CONSULTA INDIVIDUAL (/panel)
--------------------------------------------------------------------
  Bajo las credenciales hay 3 acciones:
    - Consulta ExoRenta: POST /api/consulta {tipo, numero, contraseña} -> job.
    - Obtener copia del RUT: POST /api/rut {tipo, numero, contraseña} -> PDF.
    - Certificado de ingresos/renta: visible pero "próximamente" (sin backend).
  GET  /api/job/{id}             -> estado/progreso (tipo: xls|rut)
  GET  /api/job/{id}/descargar   -> .xls de 3 hojas (Exógena/Renta/FE) o PDF del RUT
     según la extensión del archivo generado.
  El RUT se descarga desde el dashboard autenticado (enlace "Obtener copia RUT"),
  reutilizando la sesión DIAN iniciada; el PDF queda en memoria para su descarga.

------------------------------------------------------------------------
CONSULTA MASIVA (/contadores)
------------------------------------------------------------------------
  Requiere acceso_contador (activado por el admin).
  - Botón DESCARGAR PLANTILLA (/api/masiva/plantilla):
    columnas tipo_documento | numero_documento | contrasena |
    fecha_vencimiento | estado   (solo encabezados, sin fila de ejemplo)
  - POST /api/masiva/upload (multipart, .xlsx, máx 10 MB) -> batch_id.
    Valida las 3 columnas requeridas; procesa una fila por cliente,
    secuencialmente, con consulta individual.
  - GET /api/masiva/{batch_id} -> estado/progreso/detalle.
  - GET /api/masiva/{batch_id}/descargar -> ZIP con resultado_masiva.xlsx
    (estados alimentados) + clientes/*.xls (un archivo por cliente ok).
  Estados por fila: ok | error_credenciales | desconocido | excepcion.
  Al terminar, el sistema ALIMENTA:
    - estado        : resultado del cliente.
    - fecha_vencimiento: fecha del calendario DIAN (según dígitos del doc).
Re-ejecución: las filas con estado=ok se saltan (proceso resumible).
  Los batches viven en memoria (_batches) con _job_lock; se limpian tras 1h.

-----------------------------------------------------------------------
CHAT BOT (atención web en la landing)
-----------------------------------------------------------------------
  Widget flotante en / (app/static/bot.js). NO es Telegram ni Meta:
  es un asistente embebido en la propia página. Público y anónimo
  (cookie firmada 'bot', 12 h); el cliente escribe SOLO su cédula.

  Flujo:
    1) POST /api/bot/mensaje {mensaje} -> si la cédula existe, devuelve
       acciones 'rut' (copia del RUT PDF) y 'consulta' (Excel ExoRenta).
       Si no existe: 'manual' (ir al panel) / 'reintentar' / 'registro'.
    2) POST /api/bot/accion {accion} -> lanza el job (misma cola _job_lock,
       usuario 'bot:<chat_id>') y devuelve job_id.
    3) GET /api/bot/job/{id} (polling) -> en 'done' devuelve enlace
       /api/bot/descargar/<token>.
    4) GET /api/bot/descargar/<token> -> file 1-uso con vencimiento de
       15 min (segunda descarga = 403).

  Catálogo (admin):
    - POST /api/admin/clientes (multipart .xlsx, admin, RL 5) importa TODAS
      las filas de clientes_dian.xlsx (incl. estado=ok), las CIFRA con
      Fernet y las guarda en clientes_autorizados.
    - GET  /api/admin/clientes          (lista sin credenciales)
    - DELETE /api/admin/clientes/{cc}   (quita un cliente)
  Conversaciones sin actividad 15 min -> descartadas.
  Enlaces de descarga: tokens de 1-uso y 15 min; credencial nunca viaja
  en la respuesta.
